# PropPact website leads in the CRM

The public website sends each enquiry to the existing CRM. The CRM `leads` table remains the only lead store. The website does not insert a second copy and does not email a separate alert.

## CRM architecture

The CRM at `D:\My Documents\Cursor_Projects\PropPact_Lead_Management` is a Next.js application using Supabase Postgres. Production is `https://crm.proppact.co.in`. Staff sign in through Supabase Auth. Server writes that must bypass row level security use `SUPABASE_SECRET_KEY`.

Lead rows live in `public.leads`. `lead_code` is generated by the database. Source values include `WEBSITE`, `99_ACRES`, `HOUSING`, `REFERRAL`, `MANUAL`, and `OTHER`.

## 99acres flow

99acres push:

1. `POST /api/integrations/99acres/leads`
2. `acceptNinetyNineAcresPush` in `src/lib/portals/99acres-push.ts`
3. Payload fields `Name`, `Mobile`, optional `Email`, `notes`, and `Project`
4. Source is set to `99_ACRES` inside the CRM. There is no external reference, so a repeated 99acres push can insert another row. That behavior is unchanged.
5. `persistPortalLead` in `src/lib/portals/persist-portal-lead.ts`
6. Insert into `leads`, then `autoAllocateNewLead`
7. `autoAllocateNewLead` calls the database function `allocate_next_strategy_lead`
8. A new assignment calls `deliverPushForCreatedAssignment`

The 99acres route does not use an API key. Do not send website enquiries to it.

Email ingestion from 99acres is a separate Gmail path: `src/lib/ingestion/providers/99acres.ts` and `src/lib/ingestion/pipeline.ts`.

## Website endpoint

`POST https://crm.proppact.co.in/api/integrations/website/leads`

Authentication: `Authorization: Bearer <WEBSITE_LEAD_API_KEY>`

The route is anonymous to the staff session middleware and is rejected without this key. The handler is `src/app/api/integrations/website/leads/route.ts`. Parsing is `acceptWebsiteLead` in `src/lib/portals/website-lead.ts`. Saving and allocation use the same `persistPortalLead` and `autoAllocateNewLead` functions as 99acres.

The website calls this URL from `POST /api/leads` through `submitLeadToCrm` in `lib/crm-leads.ts`. The browser never sees the key.

### Request

```json
{
  "idempotencyKey": "uuid",
  "name": "Visitor name",
  "mobile": "+919560959762",
  "email": "visitor@example.com",
  "enquiryType": "project",
  "projectName": "Yuvraj Villa",
  "projectSlug": "yuvraj-villa",
  "propertySlug": null,
  "propertyTitle": null,
  "locality": "Vaidpura, Sector 10",
  "budget": "Indicative price from ₹85 lakh",
  "propertyType": null,
  "message": "Please confirm the current price.",
  "consent": true,
  "sourcePath": "/projects/yuvraj-villa",
  "utmSource": null,
  "utmMedium": null,
  "utmCampaign": null
}
```

`enquiryType` is one of `general`, `project`, `property`, `site_visit`, `seller`.

Fields such as `assignedTo` and `status` are ignored. The CRM sets status to `NEW`, temperature to `COLD`, and the owner through allocation.

### Response

Created:

```json
{
  "ok": true,
  "created": true,
  "leadCode": "PP-1001",
  "idempotency": "source_reference",
  "allocation": { "allocated": true, "error": null }
}
```

The same idempotency key again:

```json
{
  "ok": true,
  "created": false,
  "leadCode": "PP-1001",
  "idempotency": "source_reference",
  "allocation": null
}
```

`allocation` is present only when this request inserted the row. It does not include the staff id. `allocated: false` with an `error` means the lead was saved and the existing strategy did not assign anyone.

The public form shows `leadCode` as the reference. It does not show the assigned person.

## Field mapping

| Website | CRM `leads` column |
| --- | --- |
| Name | `name` |
| Indian mobile, stored as 10 digits | `mobile` |
| Email, optional | `email` |
| Fixed value | `source` = `WEBSITE` |
| `website:` plus idempotency UUID | `source_reference` |
| CRM receipt time | `received_at` |
| Project name, property title, “Sell your property”, or “General enquiry” | `requirement` |
| Locality | `preferred_location` |
| Enquiry label, or the seller’s property type | `property_type` |
| Message, project slug, property slug, budget text, source page, UTM values, consent | `remarks` |

Budget stays text inside `remarks`. It is not written to `budget_min` or `budget_max`.

Project names come from the website catalogue: Vista Homez, Madhav Kunj, Yuvraj Villa, Rudransh Urban Vista. The website overwrites the project name from the slug before calling the CRM.

## Allocation

`allocate_next_strategy_lead` does not take the lead source as an assignment input. Website leads use the active strategy already configured for other new leads. This integration does not change that strategy, its teams, or its cursor.

Assignment also sends the existing push notification through `deliverPushForCreatedAssignment`. No Resend message is sent from the website.

Follow-up rows are not created at insert time. Staff follow-up continues to use the CRM’s existing lead workflow.

## Duplicates

A unique index on `(source, source_reference)` applies when `source_reference` is not null. The website form keeps one UUID for the lifetime of that form, including a retry after a failed response. A repeated request returns the original `lead_code` and does not allocate again.

99acres pushes still have a null `source_reference`, so their existing duplicate behavior is unchanged.

## Environment variables

Website, server-only:

| Name | Purpose |
| --- | --- |
| `CRM_API_BASE_URL` | CRM origin, `https://crm.proppact.co.in` in Preview and Production |
| `CRM_WEBSITE_LEAD_API_KEY` | Same secret as the CRM key below |

CRM, server-only:

| Name | Purpose |
| --- | --- |
| `WEBSITE_LEAD_API_KEY` | Bearer secret checked by the website lead route |

Do not use a `NEXT_PUBLIC_` name. Do not set `CRM_API_BASE_URL` to localhost in production. A local website may point at a local CRM only in development.

`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `LEAD_NOTIFICATION_EMAIL`, and `LEAD_FROM_EMAIL` are not read by `POST /api/leads`.

## Local setup

1. On the CRM, set `WEBSITE_LEAD_API_KEY` in `.env.local`.
2. Restart the CRM.
3. On the website, set `CRM_API_BASE_URL` to the CRM origin you are testing and `CRM_WEBSITE_LEAD_API_KEY` to the same secret.
4. Restart the website with `npm run dev`.
5. Submit one form. The success state appears only after the CRM returns `leadCode`.

## Website deployment

In the website Vercel project, set `CRM_API_BASE_URL` and `CRM_WEBSITE_LEAD_API_KEY` for Production and Preview. Use `https://crm.proppact.co.in` as the base URL. Redeploy the website after saving the variables.

## CRM deployment

In the CRM Vercel project, set `WEBSITE_LEAD_API_KEY` for Production and Preview to the same secret. Deploy the CRM before relying on the website. Existing 99acres, Gmail, and staff environment variables stay as they are.

## Production test

Do this only after the CRM deployment that contains `POST /api/integrations/website/leads` is live, and after the website deployment that calls it is live.

1. Open `https://proppact.co.in`.
2. Open a real project, preferably Yuvraj Villa: `https://proppact.co.in/projects/yuvraj-villa`.
3. Submit one enquiry whose name makes it obvious that it is a test.
4. Success text appears only after the CRM accepts the enquiry. It includes the CRM lead reference when the API returns one.
5. Open `https://crm.proppact.co.in`.
6. Find that new lead.
7. Confirm the source is Website.
8. Confirm the project name and the message match what you submitted.
9. Confirm automatic allocation assigned the lead to the team member selected by the existing CRM rules.
10. Confirm the usual assignment notification and follow-up behavior for that person.
11. Archive or close the test lead in the CRM.

If the form says the enquiry could not be completed:

- Check the website Vercel function logs for `/api/leads`. A missing `CRM_API_BASE_URL` or `CRM_WEBSITE_LEAD_API_KEY` is a configuration error. An unauthorized response means the website key and the CRM `WEBSITE_LEAD_API_KEY` do not match.
- Check the CRM Vercel function logs for `/api/integrations/website/leads`. `not_configured` means the CRM key is missing. `unauthorized` means the bearer token was rejected. `persist_failed` means the lead was not saved.
- If the browser timed out, search the CRM for the same name and phone before submitting again. The form keeps one idempotency id, so a retry of that same page should return the original lead instead of creating a second one. A fresh page load uses a new id.

Do not copy API keys into logs, tickets, or this document.

## Safe testing

Run the CRM parser check. It does not write a lead:

```bash
npm run verify:website-lead
npm run verify:99acres-push
```

Run those commands in the CRM project.

A live test creates a real CRM lead when both environments point at the production database. Use a name that starts with “Test” and remove that lead afterwards through the CRM’s normal archive workflow. Do not send a batch of test enquiries.

Confirm in the CRM:

- one new row
- source `WEBSITE`
- requirement and remarks match the form
- `assigned_to` follows the active allocation strategy
- the assigned staff member can open the lead
- a second submit of the same form does not add another row

## Troubleshooting

| Result | Meaning |
| --- | --- |
| Website says `Missing CRM_API_BASE_URL` or `CRM_WEBSITE_LEAD_API_KEY` | Website environment is incomplete. The form must not show success. |
| CRM log `not_configured` | `WEBSITE_LEAD_API_KEY` is missing on the CRM. |
| CRM log `unauthorized` | The two keys differ. |
| `allocated: false` and the lead exists | The strategy did not assign a person. Check Settings → Allocation in the CRM. The enquiry was still saved. |
| Login page instead of JSON | The website path is not in `isAnonymousApiRoute`. |

Logs record the integration name, lead code, and whether allocation succeeded. They do not record the enquiry body.

## Rollback

Remove `CRM_API_BASE_URL` from the website environment and redeploy. Forms then return the configuration error instead of a success message. Removing the CRM route requires a CRM deploy. Leave the 99acres route in place.
